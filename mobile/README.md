# Bundled Android app and private cloud vault

`npm run build:mobile` bundles all private screens with client navigation and forwards online API calls through Capacitor HTTP. No hosted page is needed to open the app offline.

Control Room has a separate charcoal/copper/lavender design with Overview, Files, Cloud and Access & rules. Backup and Activity navigation and activity collection are removed. Finance no longer imports or enables its demo mode, including through query strings. The build rejects accidental Finance demo module inclusion.

Private cloud data lives in the existing app object storage. A random 256-bit recovery code derives an AES-GCM key and a separate access token through domain-separated SHA-256/HKDF. Only the access token is sent to the server; its hash is stored. Records and files are encrypted before upload. Large files use 4 MiB chunks and signed storage URLs, bypassing the API body size limit. Unchanged content is reused. A section index is published only after all referenced files have been verified. PostgreSQL advisory transaction locks serialize index mutations because the Neon object-storage adapter does not promise conditional writes. Revision checks stop stale devices from overwriting newer cloud copies.

Cloud capture covers complete Trip Vault, Music, Finance and Studio databases plus preferences and queued music changes. A new installation reconnects using the saved recovery code, downloads and verifies all requested sections before writing them, and rolls back completed section writes if an application write fails. Per-section source hashes show unsaved changes. Automatic upload runs after data changes, reconnects and a periodic check. Device permissions and biometric enrollment are deliberately not transferable.

The app cleanup epoch is `atlas-cloud-clean-20261102-v2`. Device data resets once before screen mounting; subsequent data remains. A short-lived, cryptographically verified GitHub Actions OIDC identity for the matching owner build authorizes the one-time server reset. A durable receipt prevents future builds from repeating that reset. App records and both managed file buckets are cleared; schema, indexes and the author configuration required by publishing remain.

The GitHub workflow verifies live cloud upload/recovery using a temporary encrypted vault, removes that temporary vault, builds current Android sources including audio permission/file export/bank capture plugins, executes the authorized test reset once and publishes the signed APK ZIP with its receipt and service status. Recovery data and credentials are never committed or printed.
